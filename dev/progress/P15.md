**Adaptations** (D-064):
1. **IC-62: the scanner parses UTF-8 bytes, not UTF-8-marked text.** The plan parsed
   `parse(text = as_utf8(lines))` and decoded literals with `str2lang()`. In a C locale the parser
   translates marked UTF-8 to the native encoding, so a prompt `"café"` became
   `"caf<U+00E9>"`: its `prompt_hash()` never matches the hash of the runtime prompt, so the call
   would never find its block by prompt (IC-62 requires exact UTF-8 prompt bytes under
   `LC_ALL=C Rscript`, document included). `doc_parse_text()` parses `os_bytes(lines)` (UTF-8
   bytes, unmarked) outside a UTF-8 locale and marked UTF-8 (as the plan did) in a UTF-8 locale
   (review round 2; round 0 parsed the bytes in every locale), and `str2lang(os_bytes(.))`
   decodes prompt literals and call texts in `doc_call_prompt()` and `doc_calls_have()`; prompts
   and texts read back pass `as_utf8()`. The parse-data columns and `getParseText()` (which cuts
   the source lines with `substr()`) then count the same unit: bytes outside a UTF-8 locale,
   characters in a UTF-8 locale (anchors only compare columns of one table). Round 0 claimed
   this split but parsed bytes everywhere, so in a UTF-8 locale the columns counted bytes and
   the texts were cut by characters (review round 2 below).
2. **Parse data is kept under `sys.source()`.** `sys.source()` sets `keep.parse.data = FALSE`
   (its `keep.parse.data` argument defaults to `keep.parse.data.pkgs`) while the sourced code
   runs, and a user may set it too. Then `getParseData()` is `NULL` and the plan's scanner finds no
   calls at all (found while building the regression harness, which used `sys.source()`).
   `doc_parse_text()` sets `options(keep.parse.data = TRUE)` around the parse and restores it with
   `on.exit(add = TRUE)`.
3. **Terminal-only parse text.** `utils::getParseData(exprs)` without `includeText = TRUE`:
   `getParseText()` reads a call's text back from the source, so results are identical, and a
   2,320-line script parses in 0.013 s instead of 0.24 s (scratch probe). Locating all 50 calls of
   a 2,400-line script takes 0.26 s in total (plan: 1.9 s).
4. **Exact keys, no NA prompt match.** `call=` is read with `h[["call"]]` (the plan's
   `doc_owned_block()` used `h$call`, which partially matches an unknown key such as `callback=`,
   the Task 1 review nit), the `label` column and site/anchor fields with `[[`. `doc_run_owner()`
   never matches a header without `prompt=` to a missing prompt hash (`NA %in% NA` is `TRUE`;
   the plan returned that block as owned and fresh). `doc_text_locate()` falls back to
   `doc_find_blocks(text)` when the call table carries no `blocks` attribute.
5. IC-74 (07 section 6, P15 row): the scanner, anchors and ownership hold no model, digest or
   image field and call no provider, so there is nothing to apply here; header `model=` values
   pass through Task 1's parser unchanged.
