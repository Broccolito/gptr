**Review round 1 (changes required; D-093).** The reviewer re-ran the filters (26 and 18 passes,
no lints) and confirmed the files were byte-identical to the plan. Findings and what changed:

1. Major, real. The plan's PATH test mocked `pcli_is_windows()` to `FALSE` with an extensionless
   `claude`; on native Windows `file.access(x, 1)` is -1 for files without an
   `.exe`/`.com`/`.cmd`/`.bat` extension, so the test failed on the `windows-latest` jobs of
   `R-CMD-check.yaml`. The test now drops that mock and creates `pcli_exe_names("claude")[[1L]]`,
   so each OS runs its own branch. Source unchanged.
2. Minor, real. A directory in `options(gptr.cli_path)` was accepted as the command. `pcli_find()`
   now signals `gptr_error_cli_missing` for it (contract 7.20), and the "missing command" test
   checks it (3 expectations).
3. Minor, real (coverage only). New tests pin a native `claude.exe` later on PATH before an
   earlier `claude.cmd` (`pcli_on_path()` order and `pcli_find()`), and the exact Unix install
   locations for claude and codex (5 expectations).
4. Nit, fixed. An `options(gptr.cli_path)` value that is not `NULL` or a list named `claude`/`codex`
   (unnamed, mis-cased or duplicated names) was silently ignored. It is now
   `gptr_error_invalid_argument` through `arg_abort()` with `arg = "options(gptr.cli_path)"`, and
   the cache records `error = "invalid options(gptr.cli_path)"` for Task 3's `status()`; an empty
   list counts as `NULL` (6 expectations).

**Review round 2 (changes required; D-093 items 5-6).** The reviewer re-ran the filters (40 and 18
passes, no lints). Findings and what changed:

1. Major, real. The plan-literal `expect_identical(pcli_codex_vendored(shim), exe)` fails on the
   `windows-latest` jobs: `exe` is a `tempfile()` path with backslashes, while
   `pcli_codex_vendored()` builds its result from `dirname(shim)`, which returns "/" on Windows.
   `pcli_codex_vendored()` now returns `normalizePath(<hit>, winslash = "/")` (its callers already
   normalised the value in `pcli_found()`), and the test compares it with
   `normalizePath(exe, winslash = "/")`. No other test compares a `dirname()`-built path with a
   `tempfile()` path (the PATH-order test builds both sides with `file.path()` from the same
   strings).
2. Minor, real. The PATH/install-location loop of `pcli_find()` returned a non-shim candidate
   without checking the execute bit, so a mode-0644 file in an install location was recorded and
   returned as the CLI (the same file on PATH is skipped by `pcli_on_path()`). On Unix the loop now
   skips a non-shim candidate whose `file.access(cand, 1L)` is not 0; shims are exempt because they
   never run (refused, or resolved to the vendored `codex.exe`), which keeps the shim tests valid
   on macOS and Linux. The options branch is unchanged (an explicit command such as
   `c(rscript_path(), ...)` is the user's choice). New test "an install location without the
   execute bit is skipped, as on PATH" (3 expectations; skipped on Windows, which has no execute
   bit).
