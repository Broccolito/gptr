**Adaptations (D-089).** The plan-literal source was corrected in six places; the rest is the
plan's code.

1. `form_encode()` escapes with `curl::curl_escape()` on `as_utf8()` values. The plan's
   `utils::URLencode(reserved = TRUE)` keeps `repeated = FALSE`, so a value that already contains
   a `%xx` sequence (`"50%25"`) was sent unencoded, and multibyte characters were split through
   the native locale. An all-`NULL` field list now gives `""` (the plan gave `"="`).
2. `query_parse()` splits each pair at its first `=` (the plan's `strsplit()` drops trailing
   empty pieces, so `x=abc==` became `abc=`), skips empty pairs (`a&&b`), and decodes with
   `curl::curl_unescape()`: `utils::URLdecode()` warns on a malformed escape and fails with
   "embedded nul" on a trailing `%`, which a pasted redirect can contain; curl keeps it as typed.
3. `oauth_parse_redirect()` and `oauth_check_metadata()` read fields with exact `[[`: `$` partial
   matching took `code_x` for a missing `code`, and would take `error_description` for a missing
   `error` or `issuer` for a missing `iss`.
4. `oauth_parse_challenge()` also reads RFC 7235 token values (`error=invalid_token`) and
   quoted-pair escapes, and returns parameter names in lower case (they are case-insensitive).
5. `oauth_check_metadata()` requires each endpoint to be one non-empty string (the plan accepted
   any character vector, so two token endpoints passed the check).
6. `oauth_authorize_url()` joins a scope vector with spaces and drops empty scopes (the plan's
   `length(scope) && nzchar(scope)` failed with "length = 2 in coercion to logical(1)").

**Source adaptations (D-090).** The rest is the plan's code.

1. **Placeholders expand in one left-to-right pass** (`mcp_expand1()`, new
   `mcp_placeholder_value()` and the PCRE `mcp_placeholder_re`). The plan re-scanned the whole
   string after every splice: a variable whose value contains `${OTHER}` was expanded again
   (against its own "spliced in literally"), more than 50 placeholders in one string stayed
   unexpanded, and a home directory or project path containing `${userHome}` or
   `${workspaceFolder}` looped for ever (`repeat`). Now a variable's value is spliced in
   literally; a `:-` default is config text, may hold balanced braces and is expanded in turn
   (`${DB:-${workspaceFolder}/data.db}` still works, as in the plan). An `NA` element stays `NA`
   (the plan stopped with "missing value where TRUE/FALSE needed"). Only a default with an
   unbalanced `{` now leaves its placeholder unexpanded.
2. **Scalars must convert** (`mcp_scalar()`): a value that does not become one non-missing
   finite scalar is `gptr_error_invalid_argument` (the plan sent `"abc"` for a number or
   `"maybe"` for a boolean as JSON `"NA"`, with a coercion warning, and `Inf` as `"Inf"`).
   **Whole numbers** (`whole()`, `mcp_number()`): `Inf` is refused; a whole number outside the
   integer range, up to 2^53 - 1 (RFC 8259 section 6), is sent as verbatim JSON with every digit
   (the plan's `as.integer(3e10)` warned and sent `"NA"`; plain `json_encode()` would keep only
   15 significant digits), also for `number` properties; an `integer` beyond 2^53 - 1 is
   refused. **A length-1 `NA` is omitted at every level** (`mcp_coerce()`), so an `NA` under
   `anyOf` no longer falls through to `null`.
3. **`mcp_value()`** uses `jsonlite::parse_json(simplifyVector = TRUE)`: the same simplification
   as `fromJSON()`, which the package avoids because it may read its input as a file or URL.
4. **Caches** (`mcp_cache_read()`, `mcp_era_get()`): a cache file that is not a JSON object
   reads as absent (the plan's `mcp_era_get()` stopped with "$ operator is invalid for atomic
   vectors"), and so does an era entry whose `era` is not `"modern"`/`"legacy"` or whose `date`
   is not one string (fields read with exact `[[`); `mcp_tools_cache_fresh()` always returns a
   flag (a non-numeric `fetched_at` or `ttl_ms` gave `NA`).
5. **Logs** (`mcp_log_append()`): text given in pieces is joined (the plan's `!nzchar(txt)` on two
   pieces stopped); rotation removes the old `.1` first, because `file.rename()` does not replace
   an existing file on Windows (the log would grow past 5 MB there).
6. **Env entries** (`mcp_expand_spec()`, new `mcp_map_chr()`): numbers and logicals of `env`
   and `headers` become their JSON text (`8080` -> `"8080"`, `TRUE` -> `"true"`) and names are
   kept, so P03's `child_env(set =)` (named strings only) accepts them in Task 4; secret
   registration walks entries by position and skips unnamed ones (the plan's `raw[[""]]` stopped
   with "subscript out of bounds"). The name is not `mcp_chr()`, which Task 6 defines in
   `R/mcp-config.R` (plan line 4364) with other behaviour.
