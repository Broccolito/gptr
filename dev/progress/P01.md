## CI Task CI-5 cross-reference (2026-10-04): hosted regressions in P01 files

Fixed test-first by the hosted CI lane. Evidence and logs: `progress/ci-hosted.md`, Task CI-5.

- `R/utils-paths.R` (Task 4's path helpers): new `path_has_ext()`, `path_ext()` and
  `path_sans_ext()` read a file extension by R 4.6's rule without `basename()`, which stops on a
  marked UTF-8 non-ASCII path in a non-UTF-8 locale and which R >= 4.6's `tools::file_ext()` and
  `tools::file_path_sans_ext()` call (D-111 item 1). `path_norm()` expands `~` before it turns
  backslashes into slashes, so its result has forward slashes whatever `user_home()` returns
  (D-111 item 2). `tests/testthat/test-utils-paths.R` gains two tests for them.
- `tests/testthat/helper-locale.R` (new): `local_name_locale()` (the C locale on macOS and
  Linux, R's UTF-8 locale on Windows, D-111 item 4) and `local_r46_file_ext()`, which installs
  R 4.6's `tools::file_ext()` and `tools::file_path_sans_ext()` in tools' namespace for the
  calling test, so any R shows the R 4.6 failure.
- `.gitattributes` (new, `* -text`) and a `tests/testthat/test-zzz.R` test: every file is checked
  out byte for byte, so the Windows runners' `core.autocrlf=true` no longer turns LF files into
  CRLF (D-111 item 3; P01 Task 21's workflow is unchanged).
