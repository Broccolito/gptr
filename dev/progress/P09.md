## Task 1 - The static guard, assignment targets and the gptr:: shim

**Precheck.** The only function from another plan that Task 1 uses is `` `%||%` `` (P01,
`R/aaa-state.R`), and it exists. The shim tests only deparse `gptr::gptr` and
`gptr::gptr_return`, so they need neither an exported `gptr()` nor P08's `gptr_return()`.

**Built.** `R/eval-guard.R` (new, L4 svc):
- `eval_guard(exprs)` returns `list(blocked, reason)`. It refuses session-ending and interactive
  calls, and `q`/`quit` anywhere (IC-67). A local binding never hides a call. It also refuses
  stdin readers and `[secret:NAME]` markers, with the `Sys.getenv()` hint.
- `eval_assign_targets(exprs)` finds `=`, the left arrow, `<<-`, `assign()`, replacement roots,
  data.table `:=` / `set*()` and `for` variables.
- `gptr_shim(exprs, envir)` rewrites to `gptr::` when the symbols are not visible from `envir`.
  It binds nothing and keeps the `srcref`.

The helpers are those of the plan. `tests/testthat/test-eval-guard.R` is the plan's 9 blocks
(52 expectations), unchanged, plus 2 blocks for the adaptations (7 after review round 1).
No export, so the document action was not run.

**Adaptations** (D-037). Each was found by probing the plan-literal source:
1. **Namespaced calls.** A `pkg::fun(...)` head now sets the call name, so the indirect-string,
   stdin and quote checks see it. Before, `base::do.call("q", list())`,
   `base::match.fun("quit")()`, `base::get("q")()`, `base::readLines("stdin")` and
   `base::scan()` all passed the guard. IC-67 lists `do.call` and `base::` as positions.
   `pkg::name` is still always refused.
2. **The guard never throws on parseable code.** Task 8's `eval_run()` calls the guard and the
   targets without a handler, and 04 section 2.2 says evaluation failures never throw. The
   changes are length and missing-argument checks in the walkers and `scan()`'s
   empty-argument default (stdin). A `function` head counts as a definition only with a pairlist
   of formals. `eval_guard_target_root()` returns `NULL` for an empty argument, so it never
   produces a `""` target. The plan-literal source raised errors on `` `=`() ``,
   `` `for`() ``, `` `function`(x) ``, `` `$`() `` and `scan(, what = 'a')`.
   - Known limit, unchanged: recursion depth. A 2,000-term sum overflows R's node stack in the
     walk, before anything is evaluated.

### Review round 1

The reviewer re-ran the gates (69, 18, no lints) and asked for changes. It found 2 major and 3
minor findings, all checked against the contract and R's semantics and all real. Each fix is
recorded in D-037 (points 2-5).
- **Major: secret markers.** The regex `[A-Za-z0-9_.-]+` missed the vault's own names, such as
  `[secret:auth:openai]` (`auth_secret_name()`). Contract 04 section 7.9 and 03 section 6.5
  refuse any literal `[secret:` marker. The fix uses the redactor's marker grammar
  (`R/auth-redact.R`) and refuses an unterminated `[secret:` with a plain `Sys.getenv()` hint.
  Strings that are not valid UTF-8 are matched bytewise; the old regex warned on them.
- **Major: empty right-hand side.** `` `=`(x, ) `` made `eval_guard_fun_defs()` throw
  'argument "rhs" is missing'. Fixed with `if (missing(rhs)) break`.
- **Minor: stdin readers.** These were missed: `readLines()` without a connection (its default
  is `stdin()`), named or later-positioned `con`/`file` arguments, and `readBin`, `readChar`,
  `read.csv2`, `read.delim` and `read.delim2`. The connection argument is now resolved by
  `match.call()` against the base or utils definition, which never evaluates anything.
  `parse()` was added: with no `text`, its default file `""` is the console. A call passing
  `...`, or one R would refuse, is not flagged.
- **Minor: `base::"q"`.** R accepts a quoted name after `::`. A length-1 string name now counts
  like a symbol in the `::` check, the head name and the walk.
- **Minor: `q`/`quit` as the function argument.** `q = 1; sapply("no", q)` calls `base::q()`
  through `match.fun()`. As the `what`/`FUN`/`f` argument (by `match.call()`) of the indirect
  calls, `q`/`quit` is now exempt only when the code defines a function of that name. Other
  positions keep the value exemption.

My own fuzz of the guard, targets and shim found 2 more defects, both plan-literal:
- `gptr_shim()` deleted a top-level `NULL` when it assigned the element back. `NULL; gptr('a')`
  threw "subscript out of bounds", and `x = 1\nNULL` lost an expression. It now rewrites calls
  only.
- `setkey(NA_character_, id)` gave an `NA` target. Target roots and `assign()` now skip `NA`.

**Regression red** (new tests against the pre-fix source):
