### Task 1 - review round 2

Reviewer verdict `changes_required`: one major and two minor findings. The reruns matched round 1:
`^s1-types$` PASS 127, neighbours FAIL 1 (the pre-existing `test-zzz.R:301`) and PASS 538, no lints

- **Major, accepted: NA subscripts in `[<-` raised an error.** In the plan-literal `[<-`, the
  `target = pos[i]` line kept NA positions. So `replace(d, mask, d[1])` with an NA in the mask,
  `d[c(NA, 2L)] = d[3]`, `cho[c(NA, 2L)] = cho[1]` and `x[NA] = clef` all failed with "NAs are not
  allowed in subscripted assignments". Base R assigns a length-1 value through such a subscript,
  and contract 5.2 requires that a same-class or bare value "keeps the class and aligns
  per-element attributes". Fix: `[<-` now applies the same subscript to an index vector,
  `from[i] = seq_along(value)` (its repeated recycle warning is suppressed because the real
  assignment has already given it). The positions with a non-NA entry are the targets, and each
  entry names the value row assigned there. NA positions, recycling, duplicate positions (the
  last one wins), negative subscripts, names, NA names and extension past the end therefore follow
  base R exactly. This also covers `d[NA_character_] = d[2]`, which extends with an NA name and
  takes the value's prob and cached; the reviewer's NA filter alone would have given that element
  NA attributes. A subscript that is entirely NA selects no target, so it merges no calibration.
  `s1_assign_attrs()` now takes `vrows` from `[<-` and reads the value's `cached` through the new
  `s1_cached()`. Also changed: `[[<-` now rejects an NA or multi-element `i` with
  `gptr_error_invalid_argument`, as base R does ("attempt to select more than one element"). The
