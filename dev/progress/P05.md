Built in `R/catalog-models.R`: the real bounded `catalog_http_request()` (and its GET wrapper
`catalog_http_get()`, the callback Tasks 2/3 forward-referenced), `catalog_refresh()` (models.dev
with ETag into `R_user_dir("gptr", "cache")`), `model_route_ready()`, `model_cli_available()`,

now P05's native discoverer, as the Task 2 note required.

- **HTTP.** One transfer on P04's reactor (`reactor_http()` + `reactor_pump(timeout =)`; P04 sets
  `followlocation = 0L`). Only this request's own unsettled transfer is cancelled, from
  `on.exit()` (pump timeout, interrupt/error unwinding the pump, oversized body), never inside a
  callback. Bodies are bounded (64 MiB; 8 MiB for local metadata); the timeout also bounds the
  spec's connect/first-byte/idle timers. Non-2xx answers return `list(status, headers, body)`
  from P04's failure condition (a 304 is P04's refused redirect, plan ambiguity 17).
- **Native Ollama discovery** (explicit only: `gptr_models(provider = "ollama", refresh = TRUE)`
  lists every installed model; `model_prepare()` asks for its one model): `/api/version`,
  `/api/tags`, `/api/show` at the base URL without its trailing `/v1`, 1 s and one attempt per
  request, never under R CMD check, refused before any request for a non-loopback endpoint
  unless the protected safety record relaxes local-only. Preserved: tag, digest, capability
  booleans (in `capabilities`), format, quantization, configured `num_ctx` (bounding the trained
  length; unknown when not configured), server version, remote markers. `decision` selects
  `type = "classifier"`/`api = "ollama-system-one"` with the typed decision record
  (`max_active = 1`); vision from the capability or projector metadata. Locality is `local` only
  for a loopback endpoint and no cloud selector/remote marker; local models get a zero metered
  price, remote ones none (unknown).
- **Evidence and preflight.** Evidence lives privately in `the$catalog$evidence` (04 section 7.0:
  no new global), written only by validated native discovery, bound to canonical origin, base
  path, model tag (`:latest` normalised), digest, server version and the registry lifecycle
  (registry environment, generation, winning provider record). `provider_preflight()` is pure;
  other routes pass through unchanged. Ollama routes need current evidence; local-only (default;
  only `safety$ollama_local_only = FALSE` relaxes it, never settings/model/project data) rejects
  non-loopback endpoints, cloud selectors, remote markers and non-local evidence; classifiers need
  model-level type/api, the decision capability and server >= 0.35.1; chat needs `completion` and
  the provider's adapter. The checked model's tools, reasoning, image input and context shrink to
  the evidence and carry its digest/server version/locality, so a prepared model is never
  silently replaced (a moved digest is refused). Public fields (`locality`, `digest`,
  `ollama$verified`, a provider's `local` hint) never attest. Staleness is a binding mismatch;
  there is no time-to-live. Replay never reaches `model_prepare()` (P08's replay guard owns that).

## Task 10 - provider_stream() glue and the HTTP transports

Built in `R/provider-registry.R` (append only): `provider_stream(model, context, opts, emit, done,
run = NULL)` (04 sections 7.5, 8.1, 8.4) with the plan's private helpers (`stream_condition()`

(at most one `start`, exactly one `done(msg)`), `stream_partial()`, `stream_fail_local()`,
`stream_normaliser_fail()`/`_finish()`, `stream_abort()`, `stream_detach()`/`stream_watch()` (abort
flag; a settled run lets go without `done`, INFRA-15), `stream_retry()`, `stream_send()`,
`stream_opts()` (IC-33 injection: the caller's `gate`/`tool_result`/`mcp_dispatch`, else deny, a
minimal `msg_tool_result()` and the `mcp.dispatch_local` service or JSON-RPC -32601),
`stream_http_spec()` (request id, model, session id and the three timeouts for P04),
`provider_rate_override()`/`stream_rate_sync()` (IC-64: settings, else catalog, set once) and the
`http_sse`/`http_ndjson`/`http_json` driver `stream_http()`. **Retry wiring (P04 Task 12, D-012):**
`opts$retry(info)` calls the committed `reactor_retry(<transfer id>, info)`; `retry =
list(max_attempts, committed = <a *_delta was emitted>, on_retry)`, whose `retry_start`/`retry_end`
notes are forwarded to `emit`; a second 2xx head resets the normaliser and splitter, and the rest
of the abandoned chunk is held back. One transfer id per request, retries included.

Adaptations (reasons in brackets; the IC-74 and cross-plan ones are D-017):

1. **IC-74 preflight.** `provider_preflight(model, provider, safety)` runs after the adapter,
   provider and `enabled` checks and before `provider_credential()` and `build()`; the adapter
   and normaliser see the checked model [07-local-ollama.md 2.1, contract 7.5: "chat transport
   ... before payload construction ... credential lookup"]. The safety record is the run's frozen
   snapshot `run$opts$safety` (contract 7.6 run option `safety`, IC-53) and/or `opts$safety`;
   when a run is given its snapshot is authoritative and a run without one counts as local-only
   (review round 1); either can only tighten (local-only unless every record present relaxes
   it), a malformed one is `invalid_argument`, none means local-only. P05 never builds it from
   settings.
2. **Decision-only models never stream.** A model of `type = "classifier"` is refused first
   (`gptr_error_not_available`, `member` = its ref, `provided_by = "a conversational model"`),
   before adapter lookup, preflight or credentials; an adapter without the stream functions of
   its transport (classify-only) is refused too (`member` = the api) [IC-74 section 6: "expected
   failures for chat on decision-only models"; contract 8.1: only `s1_request()` calls
   `classify`].
3. **No forward references to Task 11.** The plan literal dispatched to `stream_inprocess()`/
   `stream_process()`, which do not exist until Task 11 (lint `object_usage_linter`, and an
   `error` event "could not find function"). Dispatch goes through `stream_driver(transport)`,
   which has the HTTP driver only; a transport without a driver is refused before anything
   starts (`not_available`, `member` = the transport). **Task 11 adds `inprocess =
   stream_inprocess, process_jsonl = stream_process` to `stream_driver()`;** its red expectation
   (an `error` event naming the missing function) will read as a signalled `not_available`.
4. Robustness beyond the literal: a failure found locally while the transfer is live (normaliser
   `push()` error, splitter error such as a NUL byte, a retry hint `reactor_retry()` neither
   re-sent nor failed) also cancels the transfer (`stream_fail_live()`; P04 otherwise kept
   streaming into a finished stream and held a slot); a splitter/flush error at `on_done` ends
   the stream through the normaliser (P04's `reactor_call()` would only log it, so `done` would
   never run); the stream format defaults from the adapter transport when `build()` omits
   `stream`, and an unknown format or a non-list spec is `invalid_spec` (an `error` event, no
   transfer); a build error's text passes the redaction hook; rate overrides are validated with
   P04's own `ratelimit_rate()` so an invalid one is ignored instead of failing the request.
5. Tests: the plan's ten tests verbatim; plus "NDJSON lines and a whole JSON body reach the
   normaliser" (and an unknown format), "transport failures and normaliser errors end the stream
   exactly once", "a decision-only model never streams as a conversation (IC-74)" (shipped
   `ollama/clef-flash`; a classify-only adapter), "the checked model of the request preflight
   reaches the adapter (IC-74)" (safety from the run, tighten-only, malformed record), "an Ollama
   chat model fails before egress unless locality is established (IC-74)" (real preflight: no
