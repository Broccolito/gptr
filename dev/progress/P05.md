# P05 model layer task evidence

This lane implements provider registration/credentials and catalog/resolution.
Usage Task 1 is recorded separately in `P05-usage.md`; transform Tasks 4–5 have
an independent owner. IC-74 and `07-local-ollama.md` override older plan literals.
All tests use offline fixtures and synthetic credentials. No real provider,
credential file or Ollama inference is used by this implementation lane.

## Task 2 — provider records and built-in fake

Registered the 17 planned providers as data, declared the P01 fake provider,
and added provider/adapter lookup, settings and canonical origin helpers.
Ollama remains a conversational-default provider that can carry mixed native
classifier models; `ollama-system-one` is attributed to P13. Its default endpoint
uses `127.0.0.1`, auth is NULL, and real local calls remain offline=FALSE.

- Baseline red: four missing-function errors, one prior assertion passing;
  baseline green: 40 expectations.
- Transport-consistent origin tests exposed seven failures for abbreviated IPv4,
  compressed IPv6 and malformed URLs. The helper now uses P04's verified parser.
  Mixed model fields, decision limits, unknown context and remote markers survive
  provider settings unchanged; capability booleans remain separate. Green: 51.
- Independent review found case-sensitive HTTP header merging. Seven regressions
  failed before the fix. Valid names now override case-insensitively; ambiguous,
  missing and malformed names raise typed argument errors. Non-string values
  retain the documented ignored behavior. Final green: FAIL 0, ERROR 0, WARN 0,
  SKIP 0, PASS 58. Independent correction review is clear.
- Test lint is zero. Source lint reports only the plan's forward callbacks
  `provider_credential` (Task 3) and `catalog_http_get` (Task 8). These interfaces
  remain pending; this task does not establish runtime discovery or P05 package
  acceptance. No placeholder implementations were introduced. Native Ollama
  discovery replaces the generic callback path in Task 8 before publication.

## Task 3 — origin-bound provider credentials

Implemented explicit callback, vault, credential-store and environment lookup
in precedence order. Invalid endpoints fail before credential callbacks. Auth
callbacks return only handles, and default Ollama performs no cloud-key lookup.
Both the handle and current vault metadata must permit the effective origin;
stale IDs fail before transport and inactive-but-retained entries remain usable.

- Earlier credential boundaries advanced the baseline from 89 to 104 passes.
- Rebinding regressions: RED 7 failures / 105 passes. An unchanged environment
  value had overwritten an older origin restriction, and a stale handle had
  passed without a current metadata record.
- Raw environment/store registration now first preserves any existing origin,
  validates compatibility, and only then persistently binds the value. A new
  replacement value may bind independently; endpoint changes cannot rebind the
  unchanged old value. Handle-only ambient binding retains the P03 contract.
- Luna isolated validation: GREEN 112 passes, zero failures, test warnings or
  skips. Independent Astra source review cleared the origin and stale-ID fixes,
  including the raw-store path. Scoped tests lint clean; source has only the
  existing forward `catalog_http_get` callback pending Task 8.
- Evidence: ignored `dev/.validation/P05/task3-rebinding-red.log` plus Luna's
  isolated Task 3 logs. No real key files or provider calls were used.

## Task 7 — merged catalog and pure model resolution

Implemented snapshot/cache/override/provider/model/settings/discovery merge,
exact/alias/family/fuzzy references, credential/owner tie-breaking, thinking
suffix handling, fake-provider references and typed model records. Registry
identity, generation and version invalidate the catalog cache alongside config
and discovery changes. Model-level native type/api and IC-74 typed metadata
survive resolution; configured context bounds catalog context. Unknown local
IDs grant no tools, vision, reasoning or known capacity. Resolution never runs
discovery; the current discovered layer is descriptive until Task 8 preflight.

- RED 10 missing `catalog_reset` errors / PASS 76; baseline GREEN 164 and
  source/test scoped lint zero. Astra independent source review is clear.
- Additional no-discovery/exact-colon/malformed-capability and credential
  side-effect checks exposed RED 1 / PASS 171: `Sys.getenv(character())`
  returns the whole environment, falsely treating a missing provider as keyed.
  The environment presence check now requires nonempty variable names.
- Presence reads only existing vault handles and credential-store metadata;
  unlike the historical `auth_store_get()` snippet it neither registers values
  nor queries keyring. No provider callbacks or requests run during resolution.
- Final Luna GREEN 172, zero failures/warnings/skips. One test-only brace lint
  was corrected without behavior change; final source/test lint recheck is zero.
  Evidence: `catalog-models-task7-{red,green,lint}.log` and
  `catalog-models-task7-boundaries-{red,green,lint}.log`.

  known forward source callback pending the real Task 8 reactor integration;
