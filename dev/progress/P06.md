  `^[A-Za-z0-9_-]+$` in two ways:
  - `_` is refused because it separates the stamp from the id in the file name, and
    `lock_acquire()` recovers the id with `sub("^.*_", ...)`.
  - The 64-character cap keeps `<stamp>_<id>.jsonl.lock` well under file-name limits.

  New block in `test-session-object.R`: refusals for `1`, `"/../../../escaped"` and `"s_1"`, no
  registry entry for the refused id, and an adopted uuid (a different one from Task 13's fixture,
  so the strong `gptr_last()` reference cannot collide with it).
- **Minor, fixed: a torn line longer than 1 MiB was recorded from offset 0.** `file_tail_info()`
  read only the last 1 MiB. With no LF in that window, `last_lf` became 0, and `gptr.recovered`
  then named the whole file as the torn range, against 04 section 4.6 and IC-59 ("the byte range
  of a torn line"). It now reads the last byte first: a file that ends with LF costs one byte.
  Otherwise it scans backwards in 1 MiB windows until it finds an LF or reaches the start of the
  file. Recovery behaviour is otherwise unchanged. New block in `test-session-store.R`: a
  1,100,000-byte torn line after a written session gives `data = list(from = <size before>,
