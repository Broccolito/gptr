  `^[A-Za-z0-9_-]+$` in two ways:
  - `_` is refused because it separates the stamp from the id in the file name, and
    `lock_acquire()` recovers the id with `sub("^.*_", ...)`.
  - The 64-character cap keeps `<stamp>_<id>.jsonl.lock` well under file-name limits.

  New block in `test-session-object.R`: refusals for `1`, `"/../../../escaped"` and `"s_1"`, no
  registry entry for the refused id, and an adopted uuid (a different one from Task 13's fixture,
  so the strong `gptr_last()` reference cannot collide with it).
- **Minor, fixed: a torn line longer than 1 MiB was recorded from offset 0.** `file_tail_info()`
  read only the last 1 MiB. With no LF in that window, `last_lf` became 0, and `gptr.recovered`
  then named the whole file as the torn range, against 04 section 4.6 and IC-59 ("the byte range
  of a torn line"). It now reads the last byte first: a file that ends with LF costs one byte.
  Otherwise it scans backwards in 1 MiB windows until it finds an LF or reaches the start of the
  file. Recovery behaviour is otherwise unchanged. New block in `test-session-store.R`: a
  1,100,000-byte torn line after a written session gives `data = list(from = <size before>,

### Task 13 review round 1

The reviewer re-ran the focused, neighbour and broad filters green (`task13-review1-*.log`), then
asked for changes: 1 major, 2 minor findings and 1 nit. All four were checked against the
contract and are real. Each fix was made test-first.

1. **Major: a rebuilt fork reported the source's pre-fork requests as its own.** It was confirmed
   against the contract. `rebuild_usage()` read every assistant message of the file. A fork's
   file starts with the source path that `store_fork()` copied, written first by `store_open()`
   with the ids kept, up to the header's `gptr.forkOf.entry`. So the source's requests became the
   fork's rows, under the source's recorded request ids. Contract 04 section 6.5 says nothing
   live is shared with a fork, usage included, and Task 12's test has a live fork's usage hold
   only its own request. Fix: the new `rebuild_own(entries, fork)` leaves out the copied prefix,
   up to and including the first position of `forkOf.entry`. A fork at turn 0 has no
   `forkOf.entry` and copied nothing. A `forkOf.entry` missing from the file (a skipped line)
   leaves the entries unchanged. D-050 item 5.
2. **Minor: an interrupt during the rebuild was not undone.** It was confirmed against
   architecture 03 section 6.4, which records interruption with `on.exit()`, never with an
   exiting `tryCatch()`. The first version's `tryCatch(error =)` let an interrupt through. The
   half-built session stayed live, `gptr_last()` pointed at it, and the next `gptr_resume(file)`
   returned it with 0 usage rows (the red run below shows exactly this). Fix: `store_rebuild()`
   sets `done = FALSE` after `session_new()` and registers
   `on.exit(if (!done) rebuild_undo(s, file, prev_last), add = TRUE)`, then calls
   `rebuild_fill()` and sets `done = TRUE`. The new `rebuild_undo()` releases a lock this process
   took, calls `live_forget()` and restores `the$last` inside `suspendInterrupts()`. Errors now
   propagate unchanged instead of being re-signalled with `stop()`. D-050 item 4 was updated.
3. **Minor: a time that is not ISO 8601 made the session unresumable.** It was confirmed.
   `iso_ms()` returned `NA`, not `NULL`, for a string in another format or for a non-string, so
   no `%||%` fallback applied. P05's `usage_row()` then refused the `NA` start time. A header
   time gave `d$created = NA`, and `session_file_summary()` gave an `NA` `created` in
   `gptr_sessions()`. Fix: `iso_ms()` returns `NULL` for anything but one string that parses to a
   finite time, which fixes all four callers (`operator_from_json()` now falls back to
