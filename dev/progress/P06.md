## Task 2 - Usage frames and the ledger frame

Built `R/session-budget.R` (new, layer L3) and `tests/testthat/test-session-budget.R`:
`usage_columns` (the 21 section 4.3 columns, checked equal to `names(usage_empty())`),
`usage_token_columns`, `usage_conform(row)` with its column helper `usage_conform_column()`,
`usage_totals(u)`, `ledger_empty()` and `format_count(n)`. P05's real `usage_empty()` gives the
column types; P05's `usage_row()` and `usage_new()` are consumed in tests, never redefined. All
helpers are internal (`@noRd`): no `NAMESPACE`/`man/` change, so `document` was not needed.

Adaptations (behavioural ones are D-021):

1. **Missing token and cost columns are NA, not 0** [IC-74, 07 section 5 "Missing usage
   remains unknown"; D-008, D-015]. The plan's `usage_conform()` filled them with 0. Every
   missing column is now the typed NA of `usage_empty()`; a known zero in the row stays zero.
   The plan test `expect_identical(u$cost, 0)` became `expect_identical(u$cost, NA_real_)`.
2. **`usage_totals()` keeps `sum()` without `na.rm`**, so a sum over an unknown value is
   unknown, as P05's `usage_rollup()` does (plan code unchanged; behaviour now tested).
3. **`format_count()` prints an unknown count as `"unknown"`** (the contract's word for NA,
   IC-74); the plan's version errored on NA (`if (NA < 1000)`). The unit also follows the
   printed value (999.7 -> `"1.0k"`, 999999 -> `"1.0M"`; the plan gave `"1000"` and
   `"1000.0k"`).
4. **`usage_conform()` refuses instead of coercing** values of the wrong type (character
   tokens, numeric session ids, non-logical `estimated`, unparsed `started` strings), known
   numbers that are negative, infinite or NaN, and a known `started` that is infinite or NaN,
   with `gptr_error_invalid_argument` (`arg = "row$<col>"`), P05's rule for usage rows
   (`usage_time()`, `usage_rows_check()`). A non-list input, or a list that is not named,
   equal-length, non-nested columns, is refused with `arg = "row"` (helper
   `usage_conform_list()`; a `NULL` element is an absent column). The plan's `as.numeric()`
   turned `"abc"` into NA with a coercion warning, which would have invented an unknown. A bare
   logical `NA` column becomes its typed NA; an NA start stays unknown; numeric `started` is
   epoch seconds in UTC (plan); POSIXlt is accepted.
5. **Added tests** beyond the plan's four: missing-versus-known-zero semantics, rows from P05's
   real `usage_row()` passing through unchanged (an unobserved request with all-NA tokens and
   cost, and an observed one whose `usage_new()` legacy zero cache field stays 0 while its
   unpriced cost stays NA), type refusals, unknown totals, and `format_count()` unknown and
   unit-boundary cases plus the ledger column types.

Downstream notes for later P06 tasks (not changed here): Task 4's `answered_session()` fixture
omits the cache columns, so under IC-74 its footer token sum is unknown unless the fixture
states the known zeros (`cache_read = 0`, ...); the plan's footers (`session_footer()`, Task 4;

### Task 2 review round 1

Reviewer verdict: clear, with one minor finding and two nits; all three were fixed test-first.

- **Minor, fixed: a non-finite `started` passed `usage_conform()`.** `started = Inf` (epoch
  seconds) became an `Inf` POSIXct and `.POSIXct(Inf)` passed through, although P05's
  `usage_time()` and `usage_rows_check()` refuse non-finite starts, so a conformed row could be
  refused later by `usage_log_append()`/`usage_rollup()`. The POSIXct branch of
  `usage_conform_column()` now refuses an infinite or NaN start (numeric or POSIXct) with
  `arg = "row$started"`; an NA start stays unknown. Regression tests: `bad(started = Inf)`,
  `-Inf`, `NaN` and `.POSIXct(Inf, tz = "UTC")`, plus the `arg` of the refusal.
- **Nit, fixed: refusal fields untested.** The refusal test now captures conditions and asserts
  `err$arg` (`"row$input"`, `"row$started"`) and `err$expected` (contract 04 section 2.2).
- **Nit, fixed: malformed lists bypassed the classed refusal.** A nested value
  (`cost = list(total = 1)`) was flattened to `cost.total` and dropped, inventing an unknown
  cost, and unequal lengths raised base R's unclassed "differing number of rows" error. New
  helper `usage_conform_list()` checks a non-data-frame input before `as.data.frame()`: it must
  be a list of named (unique, non-empty names), atomic, dimensionless or POSIXlt columns of
  equal length, else `gptr_error_invalid_argument` with `arg = "row"`; `NULL` elements are
  dropped as absent columns. Data-frame input (every planned caller: Tasks 4, 11, 12 and P18's
  tests) is unaffected. New test block "usage_conform() refuses a malformed list instead of
  flattening or recycling it" (nested value, 3-vs-2 lengths, recycled scalar, unnamed and
  partly named elements, duplicate names, a matrix value; accepted: a `NULL` element and a
  POSIXlt start; `list()` gives zero rows).

D-021 point 3 was updated to match.
