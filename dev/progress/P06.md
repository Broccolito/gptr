  `^[A-Za-z0-9_-]+$` in two ways:
  - `_` is refused because it separates the stamp from the id in the file name, and
    `lock_acquire()` recovers the id with `sub("^.*_", ...)`.
  - The 64-character cap keeps `<stamp>_<id>.jsonl.lock` well under file-name limits.

  New block in `test-session-object.R`: refusals for `1`, `"/../../../escaped"` and `"s_1"`, no
  registry entry for the refused id, and an adopted uuid (a different one from Task 13's fixture,
  so the strong `gptr_last()` reference cannot collide with it).
- **Minor, fixed: a torn line longer than 1 MiB was recorded from offset 0.** `file_tail_info()`
  read only the last 1 MiB. With no LF in that window, `last_lf` became 0, and `gptr.recovered`
  then named the whole file as the torn range, against 04 section 4.6 and IC-59 ("the byte range
  of a torn line"). It now reads the last byte first: a file that ends with LF costs one byte.
  Otherwise it scans backwards in 1 MiB windows until it finds an LF or reaches the start of the
  file. Recovery behaviour is otherwise unchanged. New block in `test-session-store.R`: a
  1,100,000-byte torn line after a written session gives `data = list(from = <size before>,

### Task 10 review round 1

Reviewer verdict: changes required, one major and one minor. Both are real and were fixed
test-first; D-038 has two new items (5 and 6) for them.

- **Major, fixed: settlement was not exception-safe** [04 section 7.6 and the API table:
  `session_run()` "runs `s` to settlement" and "raises nothing itself"; rule R2; the plan's own
  "the session never stays `running`"]. `run_settle()` set `run$settled = TRUE`, then wrote to the
  store (`run_returns()` through `session_value_set()`, `plugin_state_persist()` through
  `session_append()`) before it set the status, cleared `live$run`, cancelled the task, timers and
  FIFO job, removed the run from the reactor, reset `home`/`scratch`/`outer`/`opts$call` and
  emitted `agent_end`. A store failure (`gptr_error_internal`, "the session store failed") escaped
  and `run_fail()` returned at once because the run was already settled: the session stayed
  `running` for good, the reactor kept the run and its home, every later `run_start()` raised
  `gptr_error_busy`, and `session_run()` returned without any condition. The same failure in
  `run_abort()`'s partial-answer append escaped `run_abort()`; under `run_abort_only()` it replaced
  the re-signalled interrupt. Changes in `R/agent-run.R`:
  - new `run_settle_persist(run, status)` runs the last-text update, `run_returns()` and
    `plugin_state_persist()` under one handler and returns the status to settle with. A run with
    no terminal condition of its own (`idle`) settles `error` with the store's condition; a run
    that ends `aborted` or already holds a condition (`error`, `max_turns`, `budget`, `blocked`)
    keeps it, and the failure is a registry diagnostic (source `session`, event `settle`). The
    reviewer proposed keeping only `error`/`aborted`; a `max_turns`, `budget` or `blocked` run is
    kept as well, because its condition explains why the run stopped and the gateway raises it,
    while a store that cannot be written fails again, visibly, at the next run's first append
    (`run_start()` settles it `error` and re-signals).
  - new `run_error_condition(e)`, shared by `run_fail()` and `run_settle_persist()`: a `gptr_error`
    as it is, else `gptr_error_internal` ("internal error in the run: ...").
  - `run_abort()` wraps its `session_append()` of the partial answer in a handler that records a
    diagnostic (event `abort`); `message_end` and the settlement follow as before.
- **Minor, fixed: an abort before the stream's `start` event stored an `unknown` model.** P01's
  `acc_new()$message()` never throws before `start`; it answers api/provider/model `"unknown"`, so
  the plan's fallback to `run$model` never ran. New `run_partial_message(run)` uses the
