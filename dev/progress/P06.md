Adaptations (behavioural ones are D-021):

1. **Missing token and cost columns are NA, not 0** [IC-74, 07 section 5 "Missing usage
   remains unknown"; D-008, D-015]. The plan's `usage_conform()` filled them with 0. Every
   missing column is now the typed NA of `usage_empty()`; a known zero in the row stays zero.
   The plan test `expect_identical(u$cost, 0)` became `expect_identical(u$cost, NA_real_)`.
2. **`usage_totals()` keeps `sum()` without `na.rm`**, so a sum over an unknown value is
   unknown, as P05's `usage_rollup()` does (plan code unchanged; behaviour now tested).
3. **`format_count()` prints an unknown count as `"unknown"`** (the contract's word for NA,
   IC-74); the plan's version errored on NA (`if (NA < 1000)`). The unit also follows the
   printed value (999.7 -> `"1.0k"`, 999999 -> `"1.0M"`; the plan gave `"1000"` and
   `"1000.0k"`).
4. **`usage_conform()` refuses instead of coercing** values of the wrong type (character
   tokens, numeric session ids, non-logical `estimated`, unparsed `started` strings), known
   numbers that are negative, infinite or NaN, and a known `started` that is infinite or NaN,
   with `gptr_error_invalid_argument` (`arg = "row$<col>"`), P05's rule for usage rows
   (`usage_time()`, `usage_rows_check()`). A non-list input, or a list that is not named,
   equal-length, non-nested columns, is refused with `arg = "row"` (helper
   `usage_conform_list()`; a `NULL` element is an absent column). The plan's `as.numeric()`
   turned `"abc"` into NA with a coercion warning, which would have invented an unknown. A bare
   logical `NA` column becomes its typed NA; an NA start stays unknown; numeric `started` is
   epoch seconds in UTC (plan); POSIXlt is accepted.
5. **Added tests** beyond the plan's four: missing-versus-known-zero semantics, rows from P05's
   real `usage_row()` passing through unchanged (an unobserved request with all-NA tokens and
   cost, and an observed one whose `usage_new()` legacy zero cache field stays 0 while its
   unpriced cost stays NA), type refusals, unknown totals, and `format_count()` unknown and
   unit-boundary cases plus the ledger column types.

omits the cache columns, so under IC-74 its footer token sum is unknown unless the fixture

### Task 3 review round 1

Reviewer verdict: clear, with two minor findings. Both are real against the contract, and both
were fixed test-first.

- **Minor, fixed: adopted ids were not validated.** `session_new()` took `opts$id` unchecked. A
  non-string id failed with base R's unclassed `get0()` "invalid first argument". A path-like id
  such as `"/../../../escaped"` was pasted into `<stamp>_<id>.jsonl`, and `lock_acquire()`'s
  recursive `dir.create()` built the intermediate directory, so the file and its lock landed
  outside `sessions/`. The reviewer reproduced this. The new helper `check_session_id(x, arg)`
  in `R/session-object.R` runs in `session_new()` before `session_by_id()`. It requires
  `check_string()` and `^[A-Za-z0-9-]{1,64}$`; anything else is `gptr_error_invalid_argument`
  with `arg = "opts$id"`. That admits IC-20 ids and the uuids of foreign Pi files (the Task 13
  fixture id `01a0ef8c-...` passes). It is stricter than the reviewer's example
  `^[A-Za-z0-9_-]+$` in two ways:
  - `_` is refused because it separates the stamp from the id in the file name, and
    `lock_acquire()` recovers the id with `sub("^.*_", ...)`.
  - The 64-character cap keeps `<stamp>_<id>.jsonl.lock` well under file-name limits.

  New block in `test-session-object.R`: refusals for `1`, `"/../../../escaped"` and `"s_1"`, no
  registry entry for the refused id, and an adopted uuid (a different one from Task 13's fixture,
  so the strong `gptr_last()` reference cannot collide with it).
- **Minor, fixed: a torn line longer than 1 MiB was recorded from offset 0.** `file_tail_info()`
  read only the last 1 MiB. With no LF in that window, `last_lf` became 0, and `gptr.recovered`
  then named the whole file as the torn range, against 04 section 4.6 and IC-59 ("the byte range
  of a torn line"). It now reads the last byte first: a file that ends with LF costs one byte.
  Otherwise it scans backwards in 1 MiB windows until it finds an LF or reaches the start of the
  file. Recovery behaviour is otherwise unchanged. New block in `test-session-store.R`: a
  1,100,000-byte torn line after a written session gives `data = list(from = <size before>,
  to = <size before> + 1100000)`.
