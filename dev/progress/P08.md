**Adaptations (D-091).** The rest is the plan's code.

1. **IC-74: `providers.<id>.local_only` is validated** (07-local-ollama.md section 5: "a scalar
   non-NA logical", default `TRUE`). The plan's `providers` validator only checked for a named
   list. `settings_check_providers()` also requires each `providers.<id>` entry to be an object
   and `local_only`, when given, to be `TRUE` or `FALSE` (`check_flag()`, `arg =
   "providers.<id>.local_only"`); `NULL` means unset, which P05's `catalog_local_only()` reads as
   the strict `TRUE`. New test "providers.<id>.local_only is TRUE or FALSE and entries are objects
   (IC-74)" (15 expectations). Validation does not make the value protected: see the obligation
   below.
2. **A lock being released is not stale.** The plan's `lock_stale()` read the pid file after a
   `file.exists()` check; when the owner removed the lock in between, `read_utf8()`'s
   `gptr_error_invalid_argument` escaped from `file_lock()` and so from `settings_write()`. An
   unreadable pid file now counts as not stale and the loop retries.
3. **The refusal names the running tool.** `control_check()` sets the condition's `tool` field to
   `run$tool_call$name` (else `"r"`), as P06's `session_control_check()` does; the plan always
   said `"r"`. New test "a control_check() refusal names the running tool call (IC-53)" (4
   expectations); against the plan-literal line it fails 1
   (`task1-red-tool-against-plan-literal.log`: `[ FAIL 1 | WARN 0 | SKIP 0 | PASS 48 ]`, `"r"`
   instead of `"bash"`).

D-091 items 4 (a settings file that is not a JSON object is never rewritten) and 5 (a rewrite
keeps the JSON types of the keys it does not change), and the second half of item 2, came from
review round 1 (below).

**Obligation for later P08 tasks (IC-74 section 5, D-014/D-017).** The protected safety record's
`ollama_local_only` must be built from human-controlled configuration only: the user settings
file and the session layer (`settings_read("user")`, `settings_read("session")`), never from the
merged layers of `settings_get()`, the project file, the user-level project file, `options()`,
`.opts` or call data; a project value may only tighten. Task 3 (`settings_get()` layering of
`providers`) and Task 9 (`gateway_run()` run options, `run$opts$safety`) must honour this, and
Task 4's `egress_check()` must use the effective origin (D-020 item 1).

**Review round 1 (changes required: 1 major, 2 minor; all three applied, D-091 items 2, 4, 5).**

1. Major, `settings_write()` with `settings_parse()`: a read-modify-write of a settings file that
   does not parse as a JSON object started from the empty list the lenient read returns, so one
   write (Task 4's egress acknowledgement, P11's `perm_rules_update()`) silently replaced the
   file and dropped every key, `permissions.deny` included (contract 11: "Unknown keys are
   preserved on rewrite"). Verified real (P11 writes through `settings_write()` expecting other
   keys preserved). Fix: new `settings_decode(path, strict = FALSE)` (the unsimplified
   `json_decode()` object; blank = empty; non-object text is, when strict, `gptr_error_workspace`
   with `path`, otherwise a diagnostic and empty, now also for a top-level array or scalar),
   `settings_parse()` = `json_simplify(settings_decode(path))` for the cached layered reads, and
   `settings_file_load(path)` (strict, never the cache, missing = empty) for the
   read-modify-write. The error is raised under the lock before any write, so the file bytes and
   the cache entry are unchanged and `on.exit()` releases the lock. **Obligation for Task 2:** its
   replacement `settings_write()` must load with `settings_file_load()` rather than
   `settings_file_read(path, fresh = TRUE)`; `trust_store()`'s read-modify-write of `trust.json`
   should use it too.
2. Minor, `lock_stale()`: a lock directory that vanished (`mtime` `NA`) counted as stale, so
   `file_lock()` could `unlink()` a lock another writer had just taken. Verified real. Fix: a
   missing lock directory, or an unknown age, is not stale (`if (!dir.exists(lock)) return(FALSE)`,
   `!is.na(age) && age > 30`).
3. Minor, one-element arrays under keys `settings_arrays()` does not know were rewritten as
   scalars (the merge base was `json_simplify()`d). Verified real (contract 11). Fix:
   `settings_write()` merges into the unsimplified object of `settings_file_load()`; the
   returned value is `json_simplify()`d as `settings_read()` returns it.
