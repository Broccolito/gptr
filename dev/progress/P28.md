### Audit scenarios A-I (gptr 8d9a388)
Harness: terminal R in a processx pty, 80 columns, TERM=xterm-256color, `peter(mode = "manual")` on a fake
provider. Request 1 streams about 2.5 s of text, then calls r `zz = 1`, which asks (E and F: request 1 runs a
read-only tool that blocks R for 3 s, request 2 asks; H: request 1 asks an ask-tool question). Later requests
echo `REQ<n> roles=...`. Every ask showed the call twice: `● r  zz = 1`, then `r  zz = 1` above the question.

| Scenario | What was typed | Key screen line | REQ roles | Outcome |
|---|---|---|---|---|
| A | `steer me` + Enter while streaming | `[gptr] steering: 'steer me'; it reaches the agent at its next step` | REQ2 `user,assistant,tool_result,operator` (the relay) | works |
| B | `use base R`, no Enter, then the ask | `allow? [y]es / [a]lways / [n]o / [?]: use base R`; Enter gives `Not an answer: 'use base R'. Type y, a, n (n <text> says what to do instead) o` / `r ? for details.` | REQ2 `user,assistant,tool_result` | text lost, mid-word wrap |

Root cause of B, C, F and H: during a run the terminal is canonical with echo off and the partial line waits in
the kernel buffer; the question's `readline()` leaves canonical mode, inherits it, shows it after the prompt and
takes it as the answer.
