**Adaptations (D-060).**
1. A rule row that wins over a shipped row replaces only the cells it supplies: the columns its
   record has, and in that row only the cells that are not NA (review round 1). The plan copied
   the whole row, so `risk_rule` rows `base::saveRDS` level 3 without `category`/`path_arg`
   (the kind requires only `package`, `function`, `level`) turned the row into category `""` and
   path argument `""`. Task 3 would then lose the path class of the saved file (`control` is level
   4), so raising a level would lower the risk.
2. Rule rows with an NA `package`, `function` or `command` are dropped; an NA `subcommand` means
   `*`, like an omitted `subcommand` column (review round 1). NA text in the other columns becomes
   `""` on a new row, and factor columns become text. With the plan's code an NA
   package row matched any `risk_lookup(fn, pkg)` of the same name as an all-NA row.
3. The `risk_table()` cache key hashes the content of the risk_rule records (`hash_xxh128()` of
   name, rows and `lower`) next to the registry generation. The plan's key (generation, count,
   names) served a stale table after a record was removed and registered again under the same
   name with other rows.
4. No behaviour change: spec fields and `subcommand` are read with `[[` (exact names, no `$`
   partial matching); a zero-row `rows` returns before any column handling; the glob rows'
   anchored regular expressions are compiled once in `risk_index_functions()` (columns `fn_re`,
   `pkg_re` of the `globs` attribute, dropped from the rows `risk_lookup()` returns).
5. Added tests: "a risk_rule row keeps the shipped columns it does not supply" (8 expectations)
   and "risk_table() sees a risk_rule registered again under the same name" (2). Against the
   plan-literal source they fail 5 expectations (category and path argument lost, an NA package
   kept and matched, the stale cache): `task1-probe-plan-literal.log`.
