## Task 1 - Member print budgets and the r-call marker

**Precheck.** Task 1 calls only P01/P02 functions, all present in `R/`: `gptr_opt()`

(`helper-fake.R`). Nothing from P06-P09 is called.

**Built.** `R/tool-namespace.R` (new, part 1 of 4):
- `r_call_new(ctx)` creates the r-call marker, an environment of class `gptr_r_call` with `ctx`,
  `images`, `dropped`, `printed`, `bridge` and `artifacts`. `ns_r_call()` finds the innermost
  marker by walking `sys.frame(k)` outwards, so there is no package-level run state.
- `r_call_attach_image()` attaches at most `gptr.r_max_images` images and counts the rest in
  `dropped` (IC-67).
- `member_budget()` is `min(gptr.helper_output_tokens, floor(0.6 x (gptr.r_output_tokens -
  printed)))` inside `r`, and `gptr.helper_output_tokens` outside (04 section 9.4).
- `lines_fit()`, `budget_head()` and `budget_head_tail()` (head 40%, tail 60%) keep whole lines
  only.
- `ns_print_lines()` writes plain UTF-8 with `writeLines()` and adds the lines' estimated tokens

- `new_gptr_text()` and `print.gptr_text()` print head and tail within the member budget, with a

**Adaptations (no contract change; item 1 is recorded as D-039 in `dev/DEVIATIONS.md`):**
1. **No promise is forced in `ns_r_call()`.** The plan's literal walker used
   `exists()` + `get()`. That forces a user's lazy argument, or calls an active binding, whenever
   a frame on the stack has one named `gptr_r_call`. For example, model code
   `f = function(gptr_r_call) gptr$read("x"); f(stop("boom"))` would raise `boom` from inside the
   member. This contradicts the plan's own docstring ("no promise is forced") and architecture
   section 6.4 R3.
   - The walker now skips such bindings with `rlang::env_binding_are_lazy()` and
     `rlang::env_binding_are_active()`. Architecture section 9 lists both as sanctioned rlang
     uses, and rlang is already in Imports.
   - The `r` tool binds the marker as an ordinary local value, so no real marker is ever skipped.
   - A test was added: "a lazy or active binding called gptr_r_call is neither forced nor called"
     (3 expectations). Its red against the plan's literal walker is a scratch reproduction, where
     the promise was forced and the active binding was called:
     `dev/.validation/P10/task1-red-lazy-binding.log`.
   - Recorded as D-039 (rationale, the sanctioned rlang calls, the added test, and PASS 31 vs
     the plan's 28).
2. **Lint fix in the test helper `with_r_call()`.** The plan writes `gptr_r_call = r_call_new(ctx)`,
   but the helper never reads the variable back, so `object_usage_linter` flags it. The helper
   now binds it with `assign("gptr_r_call", r_call_new(ctx), envir = environment())`. The meaning
   is the same, and no lint suppression is used.

## Task 2 - Paths, globs, .gitignore and the walker

**Precheck.** Task 2 calls only P01 functions, all present in `R/`: `as_utf8()` and
`read_utf8()` (`utils-encoding.R`), `check_string()`, `check_strings()`, `check_choice()`,
`check_number()`, `check_flag()` and `gptr_abort()` (`utils-conditions.R`), and `` `%||%` ``
(`aaa-state.R`). The tests use only `withr` and, for the oracle, a `git` binary on `PATH`
(`/usr/bin/git`, 2.50.1). Nothing from P06-P09 is called.

**Built.** `R/tool-walk.R` (new; architecture "L4 svc", consumed later by P11, P16 and P18):
- `fs_path()`, `tool_path_is_abs()`, `tool_path_prefix()`, `tool_path_norm()` (lexical, `..`
  never climbs above a drive, UNC share or `/`) and `resolve_tool_path()` (Pi's `resolveToCwd`:
  Unicode spaces, one leading `@`, `file://` URLs, Git-Bash/WSL drives on Windows, `~` only for
  `~`, `~/`, `~\`).
- `glob_translate()`, `glob_class()` (review round 2; it replaced round 0's `glob_class_body()`),
  `glob_anchor()` and `glob_to_regex()` (fd/Pi semantics with Pi's `**/` prefix rule for patterns
  containing `/`, a leading `/` anchors at the root; bracket expressions follow git's wildmatch).
- The ignore engine `ignore_compile()`/`ignore_eval()` (git PATTERN FORMAT: negation, anchoring,
  dir-only rules, `**`, escapes, trailing spaces), `ignore_read_lines()`, `git_root_of()` and
  `fs_case_insensitive()` (no probe file).
- `walk_tree()` (breadth-first, prunes before descending, lists symlinked directories without
  following them, 500,000-entry cap, `max_rows` per requested type) and `walk_files()` (04
  section 7.10 signature; df `path`, `size`, `mtime`, `type`, radix-sorted case-insensitively;
  attributes `root` and `truncated`).

`tests/testthat/test-tool-walk.R` is new: the plan's 11 blocks verbatim plus 10 added blocks
(4 from round 0, 3 from review round 1, 3 from review round 2; 30 added expectations).
No export, so no document action and no `NAMESPACE`/`man/` change.

**Adaptations (recorded as D-041 in `dev/DEVIATIONS.md`; no exported API change; items 5-7 of
D-041 come from review round 1 and items 8-9 from review round 2 below):**
1. **The prune list always wins.** The plan compiled it as the first ignore rules, so a
   whitelist `.gitignore` (`*`, `!*/`, `!*.R`) re-included `.git/` and `node_modules/` and the
   walker returned files under them, against contract section 7.10 ("skips `.git`,
   `node_modules`, ...") and report 11 section 4.5 ("always pruned"). The prune rules are now
   evaluated on their own and win. Added block "a negation in an ignore file never re-includes a
   pruned directory" (2 expectations; the second shows `prune = character()` still disables
   pruning).
2. **Bracket classes.** The plan escaped the `]` closing a POSIX class (`[[:digit:]]` matched
   `{[ : d i g t ]}`) and did not escape a leading `]` after the emitted `[^/` (`[!]a]b` lost its
   class). New helper `glob_class_body()` (replaced by `glob_class()` in review round 2). Added
   block "bracket classes keep POSIX classes and a literal `]` after the negation" (4
   expectations).
3. **One ignore-file precedence.** Ancestors were read `.gitignore`, `.ignore`, `.gptrignore`,
   walked directories in `list.files()` order (`.ignore` last), so a tree walked from its root and
   from a subdirectory gave different sets. Walked directories now use the ancestors' order.
   Added block ".gptrignore wins over .ignore, which wins over .gitignore, at every level"
   (2 expectations).
4. **Non-ASCII paths under `LC_ALL=C`.** `basename()`/`dirname()` error ("unable to translate")
   on marked UTF-8 there, which broke `walk_files()` for any non-ASCII root or entry name. The
   basename is taken with `sub()`, `git_root_of()`/`fs_case_insensitive()` work on `fs_path()`
   bytes, and `path.expand()` gets `fs_path(p)`. Added block "non-ASCII directory and file names
   are walked and matched in any locale" (3 expectations; its own writer goes through
   `fs_path()` so the fixture is created correctly in a C locale).

**Review round 2.** Verdict changes_required. The reviewer re-ran `^tool-walk$` (PASS 64 in
UTF-8 and under `LC_ALL=C`), the neighbours (18, 95, 176) and lint (none), and compared 20 more
rule sets with `git ls-files` (all equal); logs `task2-review2-*.log`. Findings, all confirmed
against the source and git, fixed test-first (D-041 items 8-9):
1. **Major: invalid PCRE from legal patterns.** `glob_class_body()` emitted a class body that
   PCRE reads as POSIX syntax outside a class (`[:digit:]`, `[=a=]`, `[.a.]`, the typo
   `[[:digit:]`) and reversed ranges (`[z-a]`); I also found `-` next to a POSIX class
   (`[[:digit:]-z]`), a `{` closed only by an escaped `}` (`{a,\}`) and a class splitting an
   alternation (`{a,[}]`). One such ignore line stopped `walk_files()` with a base-R error plus a
   leaked PCRE warning; `glob_to_regex()` returned a non-PCRE. Fixed by porting git's wildmatch
   bracket rules into one parser, `glob_class()` (always-escaped literals, wildmatch ranges and
   classes, backslash escapes inside brackets), with the git dialect for ignore files
   (`glob_translate(git = TRUE)` replaces the plan's `braces = FALSE`): a reversed range keeps its
   first character, an unclosed bracket or an unknown class name drops the rule (git never
   matches it), a class never matches `/`, and wildmatch's case folding when the file system is
   case-insensitive (`fold`). The git oracle exposed the folding rules: on this APFS volume git
   runs with `core.ignorecase=true`, where `[A]` matches nothing, `[*-a]` matches `b` and
   `[[:upper:]]` matches every letter. In globs a reversed range or an unknown class name is
   `invalid_argument`. Safety net as the reviewer proposed: `ignore_compile()` drops a rule whose
   PCRE does not compile, `glob_to_regex()` raises `invalid_argument`, both via P02's
   `spec_regex_ok()`. Brace matching skips escaped braces. Added blocks "bracket expressions
   follow git's wildmatch and always compile" (9 expectations: the git file set of 10 tricky
   ignore lines with no warning, 4 glob matches, 3 `invalid_argument` errors) and "case folding
   inside brackets follows git's wildmatch (core.ignorecase)" (2; `fs_case_insensitive()` mocked
   `TRUE` and `FALSE`, so Linux CI runs the folding path too).
2. **Minor: names holding a newline.** Round 0's `sub(".*/", ...)` basename stopped at a newline;
   the emitted `.*` did not cross one and `$` matched before a final newline. Fixed with
   `sub("(?s)^.*/", ...)` and `glob_anchor()`, which anchors every emitted PCRE as `(?s)^...\z`
   (ignore rules and `glob_to_regex()`). Added block "a file name holding a newline is matched
   like git" (3 expectations, skipped on Windows; expected sets taken from `git ls-files -z`).
3. **Nit: bookkeeping.** The "Built" paragraph now counts the added blocks correctly, and the
   commit note below names the other lane's entry and how to stage D-041 alone.
