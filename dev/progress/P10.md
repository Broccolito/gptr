## Task 1 - Member print budgets and the r-call marker

**Precheck.** Task 1 calls only P01/P02 functions, all present in `R/`: `gptr_opt()`
(`utils-options.R`, defaults for `helper_output_tokens`, `r_output_tokens`, `r_max_images`),
`est_tokens()` (`utils-tokens.R`), `as_utf8()` (`utils-encoding.R`), `` `%||%` ``,
`the$services` and `ext_service_set()` (`aaa-state.R`, used only by the test file's
`local_service()` helper, which later tasks call), and the test helper `local_gptr_options()`
(`helper-fake.R`). Nothing from P06-P09 is called.

**Built.** `R/tool-namespace.R` (new, part 1 of 4):
- `r_call_new(ctx)` creates the r-call marker, an environment of class `gptr_r_call` with `ctx`,
  `images`, `dropped`, `printed`, `bridge` and `artifacts`. `ns_r_call()` finds the innermost
  marker by walking `sys.frame(k)` outwards, so there is no package-level run state.
- `r_call_attach_image()` attaches at most `gptr.r_max_images` images and counts the rest in
  `dropped` (IC-67).
- `member_budget()` is `min(gptr.helper_output_tokens, floor(0.6 x (gptr.r_output_tokens -
  printed)))` inside `r`, and `gptr.helper_output_tokens` outside (04 section 9.4).
- `lines_fit()`, `budget_head()` and `budget_head_tail()` (head 40%, tail 60%) keep whole lines
  only.
- `ns_print_lines()` writes plain UTF-8 with `writeLines()` and adds the lines' estimated tokens
  to the marker's `printed` count.
- `new_gptr_text()` and `print.gptr_text()` print head and tail within the member budget, with a
  `[... n lines not printed; index the value, e.g. x[a:b]]` notice.

`tests/testthat/test-tool-namespace.R` is new (part 1 of 4). `NAMESPACE` gains
`S3method(print,gptr_text)` through the document action. That was the only `NAMESPACE` or `man/`
change, and the roxygen warnings in the log come from `provider-anthropic.R`, not this task.

**Adaptations (no contract change; item 1 is recorded as D-039 in `dev/DEVIATIONS.md`):**
1. **No promise is forced in `ns_r_call()`.** The plan's literal walker used
   `exists()` + `get()`. That forces a user's lazy argument, or calls an active binding, whenever
   a frame on the stack has one named `gptr_r_call`. For example, model code
   `f = function(gptr_r_call) gptr$read("x"); f(stop("boom"))` would raise `boom` from inside the
   member. This contradicts the plan's own docstring ("no promise is forced") and architecture
   section 6.4 R3.
   - The walker now skips such bindings with `rlang::env_binding_are_lazy()` and
     `rlang::env_binding_are_active()`. Architecture section 9 lists both as sanctioned rlang
     uses, and rlang is already in Imports.
   - The `r` tool binds the marker as an ordinary local value, so no real marker is ever skipped.
   - A test was added: "a lazy or active binding called gptr_r_call is neither forced nor called"
     (3 expectations). Its red against the plan's literal walker is a scratch reproduction, where
     the promise was forced and the active binding was called:
     `dev/.validation/P10/task1-red-lazy-binding.log`.
   - Recorded as D-039 (rationale, the sanctioned rlang calls, the added test, and PASS 31 vs
     the plan's 28).
2. **Lint fix in the test helper `with_r_call()`.** The plan writes `gptr_r_call = r_call_new(ctx)`,
   but the helper never reads the variable back, so `object_usage_linter` flags it. The helper
   now binds it with `assign("gptr_r_call", r_call_new(ctx), envir = environment())`. The meaning
   is the same, and no lint suppression is used.
