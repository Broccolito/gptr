## Task 12 — Bounded retries on the reactor

- Plan expectations: red FAIL 16 / PASS 104, green PASS 126. The counts measured here are
  higher because `test-http-retry.R` also holds the hardening regressions of Tasks 3 and 9.
- History before the pause (from the HANDOFF record; no logs were kept):
  - Initial red: **FAIL 16 / PASS 214**. Baseline green: **PASS 236**.
  - Adversarial regressions: **FAIL 10 / PASS 246**. The corrections that followed:
    - check attempt ownership and generation after callbacks;
    - install retry timers before callbacks, so cancellation and shutdown can remove them;
    - treat malformed `committed()` results as committed;
    - validate retry hints and nonretryable classes;
    - clear abandoned events and reset the attempt's byte count.
  - The follow-up green run was interrupted during Retry-After, with no final count.
- Resume, 2026-10-03 (`dev/.validation/P04/task12-resume-run1..3.log`):
  - The first run gave **FAIL 1 / PASS 274**. INFRA-21's 100 ms ticker timer was still
    armed when its pump returned, and it leaked into "retry_start cancellation leaves
    neither transfer nor timer", which asserted that no timers existed.
  - Fix: the INFRA-21 test cancels its ticker on exit. The timer assertions now check only
    for timers that the test itself created (`setdiff(reactor_ids(r$timers), before)`).
  - Then **PASS 275** twice, and scoped lint was clean (`task12-lint.log`).
- Independent review found these problems (each reproduced before the fix):
  - **M1:** `retry_start`/`retry_end` pairing.
    - A re-sent attempt got `retry_end(ok = TRUE)` at its 2xx head and a second
      `retry_end(ok = FALSE)` when it later failed (an in-stream error after commit, a
      callback error, a timer, or the network).
    - A re-send whose `http_handle()` failed went to `on_fail` without any `retry_end`.
  - **M2:** `reactor_cancel()` called from `retry_end(ok = FALSE)` was a no-op, because the
    transfer had already been removed. `on_fail` was still delivered.
  - **M3:** `reactor_retry()` had no stale-attempt guard. An old attempt's `on_bytes`, still
    running after a nested pump had started attempt 2, could cancel the healthy attempt 2
    and use up an attempt.
  - **N1:** `reactor_failure()` returned TRUE after `retry_start` had cancelled the transfer.
  - **N2:** the in-stream status stayed a double, and the request id was the client label,
    not the server's `request-id`.
  - **N3:** in-stream `timeout_*` hints got the parent `provider` instead of `timeout`.
  - **N4:** test gaps.
- Fixes:
  - `tr$retry_open` is set at `retry_start`. `reactor_retry_end()` sends exactly one
    `retry_end` per open retry and then clears the flag.
  - Every terminal failure (classified, abandoned, or a start failure) goes through
    `reactor_fail_deliver()`. While `retry_end(ok = FALSE)` runs, the transfer stays
    registered in the cancellable state `"failing"`, and `on_fail` is skipped if that
    callback cancelled the transfer.
  - `reactor_deliver_one()` records `tr$cb_attempt`, and `reactor_retry()` returns FALSE
    when the calling callback belongs to an older attempt.
  - `reactor_failure()` returns TRUE only while the transfer is still registered and is
    waiting, queued or active.
  - `reactor_retry()` keeps the coerced integer status, passes the attempt's head headers,
    and builds `c(<class>, "timeout")` for `timeout_*`.
  - `reactor_fail_final()` also fills in `seconds`/`what` for `timeout_first_byte`.
  - Deviations from the literal plan code (malformed `committed()` fails closed;
    `reactor_retry()` decides retryability by class and status) are recorded as D-012.
- New regressions:
  - one `retry_end` per retry (success, in-stream failure after the head, callback error
    after the head);
  - `retry_end(ok = FALSE)` before `on_fail` for exhausted attempts, a re-send that cannot
    start, and a re-send that hits a first-byte timeout, each also cancelled from
    `retry_end` (no `on_fail`, transfer and timers gone);
  - stream hints: retryable above `gptr.max_retry_delay` becomes `retry_after` (class, field
    and message), the integer status, the server request id, and the `timeout` parent;
  - the stale-attempt guard;
  - `reactor_retry()` returning FALSE after cancellation at `retry_start`;
  - `retry_after` added to the nonretryable-class loop, and a duplicated `withr::defer`
    removed.
- Review red: **FAIL 23 / WARN 0 / PASS 317** (`task12-review-red.log`). Every failure was
  one of the findings above.
- Review green: **FAIL 0 / WARN 0 / SKIP 0 / PASS 340**, twice (`task12-review-green.log`,
  `task12-review-green2.log`). Scoped lint of `R/http-reactor.R` and `test-http-retry.R`:
  no lints (`task12-review-lint.log`).
- Regression filters:
  - `http-reactor|http-request`: **FAIL 0 / WARN 0 / SKIP 0 / PASS 276**, 82 s including the
    60-second trickle stream and the INFRA-01 timing gates (`task12-review-reactor-request.log`).
  - `^proc`: **FAIL 0 / WARN 0 / SKIP 0 / PASS 269** (`task12-review-proc.log`).
  - All runs used the isolated runner, offline, with no real credentials.
